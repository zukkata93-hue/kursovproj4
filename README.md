# Загрузка оборудования — курсовой проект

Минимальное клиент-серверное приложение: WPF-клиент, многопоточный TCP/TLS-сервер на C# и Microsoft SQL Server. Клиент не подключается к БД напрямую. Требуются Windows для WPF, .NET 8 SDK, SQL Server (Express подойдёт). Сервер также запускается на .NET 8. Восстановление NuGet-пакетов требует доступа к nuget.org.

## Запуск

1. Создайте в SQL Server пустую базу `FactoryLoad` (например, через SSMS: `CREATE DATABASE FactoryLoad;`). Учётной записи сервера приложения нужны права на создание таблиц и чтение/изменение данных. Сервер автоматически выполняет `Server/schema.sql` при первом запуске. Не используйте существующую базу с другими таблицами с теми же именами.
2. В `Server/appsettings.json` укажите порт и строку подключения. Пример для SQL-аутентификации: `Server=localhost;Database=FactoryLoad;User Id=factory;Password=...;Encrypt=True;TrustServerCertificate=True`. Для настоящей установки настройте доверенный сертификат SQL Server и используйте `TrustServerCertificate=False`. Защитите файл конфигурации правами ОС. Создайте администратора, задав `InitialAdminLogin` и сложный `InitialAdminPassword` **до первого запуска**. После создания пользователя смените его пароль во вкладке «Пользователи» и удалите начальный пароль из конфигурации. Начальная учётная запись создаётся только при пустой таблице пользователей.
3. Создайте сертификат сервера с закрытым ключом для TLS, сохраните его в `Server/server.pfx`, а пароль пропишите в конфиге. Для учебного запуска в PowerShell от администратора, например:

   ```powershell
   $cert = New-SelfSignedCertificate -DnsName "localhost" -CertStoreLocation Cert:\CurrentUser\My -KeyExportPolicy Exportable -KeyUsage DigitalSignature -Type SSLServerAuthentication
   $password = ConvertTo-SecureString 'change-me' -AsPlainText -Force
   Export-PfxCertificate -Cert $cert -FilePath .\Server\server.pfx -Password $password
   # SHA-256 отпечаток публичного сертификата (не путать с SHA-1 Thumbprint):
   [Convert]::ToHexString([System.Security.Cryptography.SHA256]::HashData($cert.RawData))
   ```

   Передайте SHA-256 отпечаток клиенту по доверенному каналу. В `Client/clientsettings.json` задайте адрес сервера, порт и этот отпечаток в поле `CertificateSha256`. Клиент проверяет именно закреплённый отпечаток; при замене сертификата необходимо обновить конфигурацию клиента. PFX и его пароль нельзя передавать клиентам. Файлы конфигурации нужно скопировать рядом с соответствующим приложением при публикации; для `dotnet run` запускайте из каталогов проектов.
4. В двух терминалах из корня репозитория:

   ```powershell
   cd Server
   dotnet run
   # во втором терминале:
   cd Client
   dotnet run
   ```

   Разрешите входящие TCP-соединения на выбранном порту брандмауэра сервера. Войдите администратором. Клиентские и серверные часы/даты должны использовать одну локальную временную зону: приложение хранит локальные значения без часового пояса.

## Работа

* Нажмите «Обновить» на вкладке. Администратор создаёт оборудование, сотрудников и пользователей с ролью `Admin` или `Dispatcher`. Для изменения выберите строку, исправьте поля и нажмите «Сохранить»; «Новая запись» сбрасывает выбор. При редактировании пользователя пустой пароль оставляет старый; при создании пароль — минимум 8 символов. Связанные записи нельзя удалить, пока на них ссылаются другие записи.
* Диспетчер создаёт и редактирует заказы, указывая ID оборудования и при необходимости сотрудника. Статусы заказа: `New`, `InProgress`, `Done`. Они меняются вручную.
* Во вкладке «События» укажите ID оборудования, необязательный ID назначенного ему заказа и статус `Work` (работа), `Idle` (простой), `Setup` (наладка). Для простоя причина обязательна. Начало нового события автоматически завершает предыдущее на этом оборудовании; кнопка завершения закрывает активное событие. Время устанавливается на сервере. `NoEvent` означает отсутствие активного события, а не подтверждённый простой.
* Аналитика строится по пересечению событий с выбранным полуоткрытым интервалом [начало, конец), включая активные события до текущего времени сервера. Загрузка = минуты работы / вся длительность периода × 100%; незарегистрированное время не считается простоем. Наладка показана отдельно. Кнопки выбирают последние 8 часов, сутки или неделю; можно задать произвольную смену. Таблица и столбчатая диаграмма показывают результат; текстовый отчёт сохраняется на клиенте. После расчёта изменение полей периода не меняет уже рассчитанный отчёт.
* Данные сохраняются в SQL Server сразу после каждой операции и загружаются кнопкой «Обновить». Администратор может запустить резервное копирование на вкладке «Резервное копирование»: путь указывается **на компьютере SQL Server**, SQL Server должен иметь права на запись, а учётная запись подключения — право `BACKUP DATABASE`. Храните копии в защищённом месте и регулярно проверяйте восстановление через SSMS / `RESTORE DATABASE`; резервная копия содержит конфиденциальные данные и не шифруется самим приложением. Настройте шифрование хранения/копий средствами SQL Server или ОС.

## Безопасность и ограничения

Пароли хранятся как PBKDF2-SHA256 с индивидуальной случайной солью (210 000 итераций). Соединение клиента с сервером использует TLS 1.2/1.3 с закреплением сертификата. Разграничение прав проверяется на сервере, SQL-параметры используются для пользовательских данных. Учебная версия не содержит блокировки после неудачных входов, аудита действий, ротации ключей и централизованного управления сертификатами; не предназначена для открытого интернета или промышленной эксплуатации без дополнительного усиления защиты. Для SQL Server также следует включить проверяемое шифрование соединения. Локальные файлы отчётов не шифруются.

## Проверка

1. Запустите сервер и двух клиентов; проверьте одновременную работу и вход с неправильным паролем.
2. Создайте диспетчера и войдите им: изменение оборудования, сотрудников и пользователей, а также резервное копирование недоступны.
3. Создайте оборудование и заказ, начните `Work`, затем `Idle` с причиной, завершите событие. Обновите списки; проверьте времена и сохранность после перезапуска сервера. Попытка указать чужой заказ или простой без причины должна отклоняться.
4. Рассчитайте период, включающий события, проверьте минуты и процент, сохраните и откройте текстовый отчёт. Проверьте пустой период и неправильные даты.
5. Проверьте запрет удаления оборудования с заказом, резервное копирование и восстановление копии на тестовой базе. Проверьте отказ подключения с неверным отпечатком сертификата.

Основные пользовательские сценарии: вход, просмотр текущего состояния, ведение оборудования, сотрудников и пользователей, назначение и изменение заказа, запуск работы, регистрация простоя и наладки, завершение события, просмотр истории, анализ периода, сохранение отчёта, резервное копирование. SQL-схема содержит пять связанных сущностей, внешние ключи и ограничение одного открытого события на оборудование.
